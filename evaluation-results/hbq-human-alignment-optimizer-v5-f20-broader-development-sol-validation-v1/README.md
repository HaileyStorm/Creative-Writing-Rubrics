# Broader HANNA Sol validation

This is a provider-free preparation/execution scaffold for a fresh Sol
descriptive follow-on to the completed broader Grok development result. Before
preparation, it requires the exact committed Grok result, its collector and
execution root, and a replay of that result against the frozen seven-group
schedule.

The baseline and admitted parent are always scheduled. If the Grok winner is
the parent, the schedule has 14 cells; if it is exactly one admitted
single-factor descendant, the schedule has 21. A baseline, unknown, or
otherwise unadmitted winner is rejected. The seven baseline payloads are
rebuilt from the pinned materialization parent instruction/profile; every
parent or descendant Sol payload is byte-identical to its corresponding Grok
payload.

Preparation writes staged local-first disclosure and route bindings with zero
provider calls. The inherited V4 lifecycle has two Sol lanes, tools disabled,
and no-resend handling. Native endpoint-contact cardinality remains unproven.
Sol is descriptive validation only: it neither re-selects the Grok candidate
nor opens confirmation, generalization, promotion, runtime, or pooled-endpoint
claims.

No live result is ready from this package until a complete Grok result is
committed and all replay inputs are supplied.
