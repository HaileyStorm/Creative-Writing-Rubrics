# Batch curve v2: frozen executable protocol

This package contains no provider output, score, coverage, recommendation, or validated-size claim. Its offline fake-endpoint path proves only the local schedule, journal, exact-question coverage, analysis formulas, and verifier semantics.

The screen fixes thirteen sizes—1, 2, 4, 8, 12, 16, 24, 32, 48, 64, 96, 128, and all-in-one—and runs each three times in frozen order. Every cell binds the same source bytes, compiled **178-leaf** sequence (domain, hard-gate, supplemental, and penalty leaves), model stack, and retry policy. `all-in-one` is the full frozen sequence, never a domain-only shortcut.

## Execution and privacy boundary

`batch_curve_harness.py` has no live provider client; its runner takes an injected offline fake endpoint. It writes a planned/accepted/completed journal and rejects reordered, incomplete, duplicated, or projection-mutated records. A real adapter is separate work: before its first call, review the exact destination, outbound payload, existing-session authorization, local retention, and provider-identity mapping in `study-contract.json`. Credentials and provider bodies are not artifacts; immutable local provenance keeps only permitted redacted receipts and hashes.

## Recommendation rule

There is no default size. A stack-specific recommendation may name only the largest size with successful completed empirical deep validation on that exact full stack. Its cap comes from journal-backed accepted calls whose ordered IDs reconstruct the requested full batch; a declaration cannot raise it. Offline mechanism support, derived manual evidence, another format, or a diagnostic experiment is not a recommendation and cannot exceed that stack’s largest validated size.

## Deterministic measures and bracket

The harness implements the contract’s three-repeat leaf-agreement, modal-label, nominal-alpha, score-deviation, schema, quote-grounding, confidence-secondary, and position formulas. Canonical score, coverage, bounds, and status are unchanged. Assessed-confidence mass is not coverage, and confidence-weighted sensitivity is not score.

Every ladder member is screened first. The deterministic state machine records each outcome, then emits only observed adjacent transitions for deep bracket validation; it never infers an unexecuted result. The deeper eleven-item HANNA gate remains required before any recommendation.

## Offline mechanism evidence

[offline-mechanism-matrix.json](offline-mechanism-matrix.json) is generated from the current 85-bundle catalog by `generated_matrix_document`. It binds each row to its compiled-question projection/hash, frozen partition shapes and remainders, fixture score reconstruction, and secondary confidence extraction. The eight representative format stacks have independent selection hashes and findings. They do not show that a batch size works in production.

The frozen projection, provider disclosure, formulas, state transitions, and cross-format protocol are in [study-contract.json](study-contract.json). Its canonical projection is pinned in [study-contract.projection.sha256](study-contract.projection.sha256); the harness rejects a contract whose bytes no longer produce that digest. [manual-stack-fixtures.json](manual-stack-fixtures.json) fixes manual format-stack checks and verifies them through direct core compilation, not matrix regeneration.
