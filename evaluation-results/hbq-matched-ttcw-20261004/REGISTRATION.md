# Frozen matched TTCW development comparison

This is a new comparison on already opened development evidence, not an untouched confirmation study or human alignment certification. Preparation reads only three pinned source files and the exact HBQ artifacts referenced by the pinned plan. It never reads expert labels, annotation CSVs, or unused MFA targets/rationales. It makes no provider calls and grants no execution authority. Source story text, original test prompts, source-generator mapping, and executable requests belong exclusively in the supplied private output directory outside this repository.

The cohort is all 36 eligible AI stories, twelve plots with three generators each. Twelve URL-only New Yorker references are excluded. All arms receive the same complete story and retained adult literary standalone context; titles, generator identity, plot summary, and labels are absent from outbound payloads. The arm definitions record source hashes and adaptations. HBQ preserves retained prompt bytes and all 178 questions. TTCW preserves each literal question and interpretive definition; replacing terminal chain-of-thought/list-enumeration instructions and combining fourteen questions is an adaptation. Scalar descendants introduce an explicit abstention envelope. Oregon remains a research implementation with an educational/adult literary target mismatch. No baseline is established as strongest by existing TTCW evidence.

Both endpoints together have 3,108 requests. Initial requests cover all works before the repeat phase. Within each generator, sort the twelve stories by UTF-8 byte length then content hash, partition into three four-story strata, and select the lower median of each (positions 1, 5, 9, zero based). These nine distinct stories receive two additional identical-contract repetitions of all five story-scoring arms. Repeat pairs are two per generator-pair type, across six distinct plots, selected by deterministic seeded hashes before model outcomes; each receives two additional repetitions in both orders. These are source metadata selections, never quality/outcome selections. The manifest records actual selected opaque IDs and strata. Shuffle units by SHA-256(seed, unit) within initial/repeat phases, retaining HBQ's internal batch order; hash-alternate endpoint lead. Repetitions are fresh logical samples even when prompt bytes match. They add no independent works or humans. Order reversal is a named pairwise condition, not an additional independent pair.

Every private request pins prompt/schema bytes and hashes, endpoint label, logical condition, repetition, orientation, batch and question IDs. Request hashes cover these fields and ordinal. The manifest pins every emitted artifact, all public arm assets, source pins, retained runtime commitments, exact counts, transmission byte totals, and its own content excluding its self-hash field. Schemas are preflighted with the shared offline Grok/Sol subset validator. Singleton enums replace const; unsupported maxItems is omitted and exact array cardinality, identity uniqueness, status/result consistency, Oregon sums, and contiguous source quotations are enforced by validate_response.py. Record retained and emitted HBQ schema hashes; this schema-only portability conversion does not change retained user prompts or criterion inventory.
