## Reproduction and scope limits

The public package contains README.md, aggregate.json and regenerate.py. Only
aggregate numbers, qualified scope statements and hash/byte commitments appear;
poem text, quotes, individual verdicts, private paths, account identities, native
judge IDs, raw case/family IDs and private worklogs are excluded.

With Python3.12 and the exact retained private closed report and metadata:

```text
python -B regenerate.py --report <closed1396-report.json> --readback <closed-input-readback.json> --receipt <recovery-receipt.json> --output <new-aggregate.json>
```

Inputs are pinned by SHA256 and size. The embedded lexical selector reads only
allowlisted aggregate/metadata fields; unrequested story/native/verdict fields
are skipped. Temporary opaque IDs only join form/repeat metadata and are never
emitted. The command creates a fresh aggregate file and performs no source imports,
native/scientific replay, scorer execution, provider contact or new judgment.
It does not reconstruct original admission, historical runtime controls or human
validity. Private retained inputs remain required; no public case-level regeneration
route is claimed. The canonical baseline stays unpromoted and the full research
program remains incomplete.
