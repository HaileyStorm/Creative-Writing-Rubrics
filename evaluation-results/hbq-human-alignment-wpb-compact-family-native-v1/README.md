# WPB compact-family native executor v2

This package materializes and settles the 129 endpoint-neutral WPB compact-family tasks from the immutable r3 freeze: 105 TRAIN and 24 DEV pairs. It is a thin transport boundary around the reviewed compact core; it does not change its coarse `core` / `craft` / `form` proxy, local target handling, TRAIN-only Optuna fit, DEV selection, or closed confirmation partition.

Sol remains on the unchanged `prepare_all`, `execute_one`, and `execute_wave` path. Its fixed all-zero V16 transport sentinel is not a WPB label and is never outbound. The local targets, category, source model, preferred side, and source scores are never copied into a provider payload.

Grok now uses a bounded renewal chain: `create_campaign`, `prepare_next_batch`, `execute_batch`, and `settle_batch`. `create_campaign` commits the globally ordered 129 cell IDs, payload hashes, partitions, core, executor, contract, and one global acknowledgement. `prepare_next_batch` is provider-free and selects the next deterministic eligible subset of at most ten cells. It binds the predecessor settlement, fresh route proof and expiry, and a batch acknowledgement that does not hash its own plan. Native per-cell artifacts live at `batches/NNNN/execution/`, so campaign metadata remains separate from the inherited lifecycle inventory.

`execute_batch` requires `allow_remote=True`. Its default uses the pinned shared `run_grok_native_request` API once, with the frozen scoring schema, one turn, a fresh session ID, the prepared-route hash, and the local before-contact checkpoint. It reads the original successful response bytes through the returned descriptor and preserves the prompt, response, and shared receipt without reconstructing a provider envelope. Test factories are controlled overrides. Setup completes before `execution-active.json` is created; only the owner's exact marker is cleared after all owned futures settle. A crash marker remains fail-closed for manual recovery. `prepare_next_batch` and `settle_batch` reject any active marker. The guard has no retry or fallback path. Settlements re-derive exact claims and artifact hashes. Claimed or terminal cells are consumed forever; only claim-free, artifact-backed preparations can enter a successor. No code infers liveness from a PID or kills a process.

`report` independently reloads the pinned core and r3 freeze, follows every immutable batch settlement, re-admits the exact 129 completed cells, and permits a different governed route proof per batch. Every completed Grok cell must also retain a canonical shared-native result that binds the admitted request bytes, prompt, response schema, raw envelope descriptor, structured output, route, runtime identity, and settings. It rejects partial campaigns, duplicate identities, duplicate completed cells, missing or altered shared evidence, endpoint pooling, runtime fitting, promotion, or confirmation.

No command-line entry point is provided. A reviewed caller owns route refresh, outbound disclosure, and the explicit decision to make provider contact.
