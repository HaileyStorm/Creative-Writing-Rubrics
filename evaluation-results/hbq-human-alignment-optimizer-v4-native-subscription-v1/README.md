# HANNA v4 native-subscription executor v1

This provider-free successor preserves v3's exact task, candidate instruction,
candidate profile, response schema, prompt, and story bytes while replacing its
unexecuted API-shaped Sol route with honest native subscription descriptors.
Grok uses the Grok Build saved-session route. Sol validation uses Codex through a
ChatGPT subscription and records requested/local effective settings only; it is
never relabelled as Chat Completions, OpenAI API, or provider model attestation.

The mandatory gate is the 100 frozen development cells: 65 Grok-primary cells
over all 13 development items and five candidates, followed by 35 Sol-validation
cells over the seven group representatives and five candidates. The predecessor's
360 training cells remain a committed, optional development-only DSPy/Optuna pool;
they are not runtime-dispatchable and neither package is a runtime dependency.
Confirmation remains unopened with zero scheduled cells.

Preparation writes the exact outbound payload and local-first disclosure, then
requires independently verified acknowledgement and current zero-charge subscription
proof. Dispatch writes an exclusive intent immediately before its sole contact.
Anything uncertain after intent becomes `reconcile_required` and is never resent.
The live gate, runner, and native-request verifier are deliberately absent private
seams. Tests inject provider-free implementations; this package makes no live-route,
provider-contact, empirical-promotion, or confirmation claim by itself.

The evidence directory is an exact state machine: prepared, intent-only unsettled,
reconciliation-required, or fully returned-unprojected. Orphan/partial contact files
and malformed resume records fail closed. Owned evidence reads reject reparse points
through the complete ancestry and use stable non-delete-shared Windows handles before
parsing or hashing. Grok request/session IDs must match its envelope. Sol projection
requires an independent local receipt binding the Codex contact and session IDs while
remaining explicitly non-provider-attested. Live execution remains **NO-GO** until the
three absent production seams and reviewed native adapters are independently bound.

Grok evidence is a strict structured-output CLI envelope with the CLI-reported model
and unattested reasoning recorded separately. Codex evidence is one strict final JSON
object plus local effective-settings evidence proving the requested model/profile and
tool-free invocation. Codex has no provider-reported model field, by design.
