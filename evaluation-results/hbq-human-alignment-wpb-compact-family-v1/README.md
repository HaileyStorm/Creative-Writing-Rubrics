# WPB compact-family development screen v1

This package is an economical cross-format development screen for the immutable WPB r3 freeze: 105 TRAIN and 24 DEV pairs. It is a handcrafted coarse `core` / `craft` / `form` proxy inspired by the pinned short-story component family masses, not canonical HBQ module semantics or a full 179-question HBQ result.

The package accepts only the exact five r3 artifacts pinned in [experiment-contract.json](experiment-contract.json), then verifies their canonical bytes, source-program commitment, source lineage, split commitment, and every local target's selected-row/category/partition/source-row binding. It rejects r2, a joint rehash, changed preferred sides, or changed categories.

`build_tasks(freeze_root)` emits 129 canonical JSON payload bytes. The payload has a pinned response schema, explicit `BEGIN`/`END` untrusted-data boundaries, and a rule not to follow quoted content. It uses format-appropriate craft and requested-form/genre/structure language. It excludes category, source model, preference direction, chosen/rejected labels, and 0–3 construction scores; each task gets identical Grok and Sol payload hashes.

Scores are ordinal 1–5 with nonempty evidence capped at 180 characters. `not_assessable` rejects a measurement before numeric use. A model-supplied winner is diagnostic only: local analysis recomputes the winner using canonical base family mass times positive multipliers, with the pinned 0.15 tie threshold. It reports endpoint-separated category-macro chosen-over-rejected accuracy and win/tie/loss—not MAE.

`fit_train_select_dev` imports Optuna lazily, fits positive multipliers on TRAIN, then selects all-one or that fit on DEV. It has no confirmation opening, runtime, promotion, or endpoint-pooling authority. Analysis returns ordered task/target/measurement commitments and `native_admission: not_claimed`; parsed-response binding is not provider-contact proof.
