# HANNA v4 lean development pilot

This separate development pilot freezes a much smaller empirical search than the retained 360-cell package: 25 Grok training cells across five items and five frozen candidates, plus 10 matched Sol training cells across two of those items. Optuna 4.9.0 may select only from independently reverified persisted training roots: admitted Grok roots bind an admission proof and source receipt, while Sol roots bind the pinned exec-v3 local-lifecycle receipt. Sol remains `local_codex_lifecycle_received_native_contact_unproven`, not native endpoint proof. The 65 existing/remaining mandatory Grok cells must successfully validate the training-frozen choice against an explicit threshold before the seven late-bound Sol rows open; a veto cannot substitute another candidate. The two-item sprinkled Sol training correlation is only an optimizer component, not a stable alignment estimate.

DSPy 3.3.1 is a real `Predict` program: it recomputes the verified Optuna result from persisted training roots, then receives the frozen parent instruction/profile bytes and exact result/diagnostic bytes. It returns exact descendant instruction/profile bytes plus lineage and hashes. It has no runtime, selection, Sol-validation, or confirmation authority. Confirmation has no cells or execution surface.

The package exposes provider-free prepare, ingest, and freeze functions only. It refuses caller aggregates, raw envelopes, synthetic cell shapes, missing/misbound persisted roots, and absent/misbound provider-route preflight. It performs no provider dispatch. The smallest remaining live gap is a thin governed adapter that emits these root references from existing runners, then collects the frozen cells without retrying any terminal predecessor root.
