# Desc18 contingent Sol veto

This is the contingent Sol half of the public/open Fresh96 replication.  It
pins the independently replayed Grok optimizer result and its reconciliation
successor.  It will not trust a result file merely because it has the right
name: reconciliation and optimization are replayed before a route is read or
an output root is created.

Only the frozen child20 qualifier can open this executor.  A
non-qualifier returns a zero-call result before it creates an output root or
reads a Sol route.  A qualifier prepares the exact 64 schedule payload bytes
(descendant13 and child20 over 32 public/open items in 16 groups), then uses
the pinned Desc16 Sol lifecycle with at most ten lanes.  Sol is a veto only:
there is no candidate substitution, endpoint pooling, confirmation, reserve,
promotion, runtime selection, or generalization claim.

Every response is required to carry the complete six-dimension
`scores`/`evidence`/`coverage` object.  Scores must be finite 0--5 values and
evidence must be substantive text, not a placeholder, a workspace search, or
a path/pointer.  Process-launch receipts are exact; native endpoint contact
cardinality remains explicitly unproven.
